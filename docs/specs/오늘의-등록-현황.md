## Problem Statement

업무운영팀 담당자는 오늘 기준가 파일이 들어왔는지, 등록까지 끝났는지를 매번 직접 챙겨야 한다. 화면을 열어보지 않으면 오늘 업무가 끝났는지 알 방법이 없다.

## Solution

화면을 열면 바로 오늘 기준가 파일이 업로드됐는지, 등록까지 끝났는지, 이상 있는 항목이 남아있는지를 한눈에 보여준다. 상태에 따라 다음에 해야 할 일(업로드하기, 확인하러 가기)로 바로 이동할 수 있게 해준다.

## User Stories

1. As a 업무운영팀 담당자, I want 홈 화면을 열면 오늘 기준가 파일이 업로드됐는지 바로 보이는 것, so that 따로 확인하러 들어가지 않아도 된다.
2. As a 업무운영팀 담당자, I want 오늘 아직 파일이 업로드되지 않았으면 "아직 업로드 안 됨"이라고 표시되는 것, so that 오늘 할 일이 남았다는 걸 바로 안다.
3. As a 업무운영팀 담당자, I want 업로드는 됐지만 등록이 덜 끝났거나 이상 항목이 남아있으면 그 상태와 건수가 보이는 것, so that 마저 처리해야 할 게 있다는 걸 놓치지 않는다.
4. As a 업무운영팀 담당자, I want 오늘 등록까지 전부 끝났으면 "오늘 등록 완료"라고 명확히 보이는 것, so that 더 신경 쓰지 않아도 된다는 걸 안심할 수 있다.
5. As a 업무운영팀 담당자, I want 전체 건수 중 등록된 건수와 이상 건수를 숫자로 보는 것, so that 오늘 처리 상황을 정확히 파악할 수 있다.
6. As a 업무운영팀 담당자, I want 아직 업로드 안 된 상태에서 표시를 클릭하면 바로 업로드 화면으로 이동하는 것, so that 클릭 한 번으로 다음 행동을 할 수 있다.
7. As a 업무운영팀 담당자, I want 업로드는 됐지만 등록이 안 끝난 상태에서 표시를 클릭하면 바로 해당 확인 화면으로 이동하는 것, so that 업로드 목록을 따로 찾지 않아도 된다.
8. As a 업무운영팀 담당자, I want 홈 화면을 열 때마다 최신 상태로 보이는 것, so that 예전 상태를 보고 착각하지 않는다.

## Implementation Decisions

- 새 API `GET /api/price-uploads/today`: 오늘 날짜(`upload_date` = 오늘)의 `price_uploads`를 조회하고, 있으면 그 업로드에 속한 `price_records`를 `status`별로 집계(`pending`/`issue`/`registered` 건수)해서 함께 돌려준다. 오늘 업로드가 없으면 "없음" 상태를 돌려준다.
- 상태는 세 가지로 정리한다: `not_uploaded`(오늘 업로드 없음), `needs_review`(업로드는 있지만 `pending` 또는 `issue` 레코드가 남음), `completed`(업로드가 있고 모든 레코드가 `registered`).
- `app/page.tsx`(홈 화면)를 이 기능의 화면으로 교체한다: 상태에 맞는 문구와 Badge(gray=업로드 전, yellow=확인 필요, green=완료), 건수 요약(예: "정상 48건 · 이상 2건 · 등록완료 46건")을 카드로 보여준다.
- `not_uploaded` 상태의 카드에는 기준가-파일-업로드 화면으로 가는 버튼을, `needs_review` 상태의 카드에는 기준가-데이터-확인및등록 화면(해당 업로드)으로 가는 버튼을 둔다. `completed` 상태에는 별도 이동 버튼 없이 완료 문구만 보여준다.

## Out of Scope

- 파일이 늦게 오거나 안 왔을 때 담당자에게 알림(이메일, 메신저 등)을 자동으로 보내는 기능 — PRD에서 범위 밖으로 정해짐. 이 화면을 열어봐야 알 수 있는 수준까지만 다룬다.
- 오늘이 아닌 과거 날짜들의 미등록 현황을 한 번에 모아 보여주는 것 — 등록-이력-조회 기능에서 다룬다.

## Further Notes

- 이 화면이 참조하는 상태(`pending`/`issue`/`registered`, `price_uploads.status`)는 기준가-데이터-확인및등록 기능에서 정의한 스키마를 그대로 사용한다.
