## Problem Statement

업무운영팀 담당자는 업로드된 기준가 데이터를 눈으로 하나하나 확인한 뒤 펀드 운용시스템에 직접 등록해줘야 한다. 이 과정이 매번 수작업이라 번거롭고, 빠지거나 이상한 값이 섞여 있어도 눈으로 걸러내기 쉽지 않다.

## Solution

업로드된 기준가 데이터를 펀드별로 한눈에 볼 수 있는 화면을 제공하고, 빠지거나 이상한 값이 있는 항목은 눈에 띄게 표시해준다. 이상 없는 항목은 등록 버튼 한 번으로 바로 등록 처리하고, 이상 있는 항목은 등록에서 제외해서 평가사에게 재확인을 요청할 수 있게 남겨둔다.

## User Stories

1. As a 업무운영팀 담당자, I want 업로드된 펀드별 기준가 목록을 표로 보는 것, so that 파일을 직접 열지 않아도 오늘 들어온 데이터를 바로 볼 수 있다.
2. As a 업무운영팀 담당자, I want 값이 빠졌거나 이상한 항목이 눈에 띄게(색으로) 표시되는 것, so that 문제 있는 항목을 놓치지 않고 걸러낼 수 있다.
3. As a 업무운영팀 담당자, I want 이상하다고 표시된 항목에 왜 이상한지(값이 없음, 값이 이상함) 이유가 같이 보이는 것, so that 평가사에게 무엇을 재확인해야 하는지 바로 알 수 있다.
4. As a 업무운영팀 담당자, I want 이상 없는 항목들을 등록 버튼 한 번으로 한꺼번에 등록하는 것, so that 펀드마다 따로 등록하지 않아도 된다.
5. As a 업무운영팀 담당자, I want 이상 있는 항목은 등록 대상에서 자동으로 빠지는 것, so that 잘못된 값이 실수로 등록되지 않는다.
6. As a 업무운영팀 담당자, I want 등록 버튼을 누르기 전에 몇 건이 등록되는지 확인 메시지를 한 번 더 보는 것, so that 실수로 잘못 누르지 않는다.
7. As a 업무운영팀 담당자, I want 등록이 끝나면 몇 건 등록됐고 몇 건 이상으로 제외됐는지 요약을 보는 것, so that 오늘 처리 결과를 바로 알 수 있다.
8. As a 업무운영팀 담당자, I want 이미 등록된 항목은 "등록완료" 표시가 남아있는 것, so that 같은 항목을 실수로 다시 등록하지 않는다.
9. As a 업무운영팀 담당자, I want 이상 있던 항목을 평가사 재확인 후 다시 받은 파일을 올리면 그 항목만 다시 검증되는 것, so that 처음부터 전체를 다시 확인하지 않아도 된다.
10. As a 업무운영팀 담당자, I want 이상 항목이 하나도 없을 때는 바로 전체 등록이 가능한 것, so that 문제 없는 날은 빠르게 끝낼 수 있다.
11. As a 업무운영팀 담당자, I want 오늘 날짜가 아닌 예전 업로드 건도 이 화면에서 열어서 확인할 수 있는 것, so that 놓친 날이 있어도 나중에 처리할 수 있다.
12. As a 업무운영팀 담당자, I want 등록 처리 중에 화면이 멈춘 것처럼 보이지 않게 처리 중 표시가 뜨는 것, so that 등록이 잘 진행되고 있는지 알 수 있다.

## Implementation Decisions

- `price_records`에 `status`(`pending` | `issue` | `registered`) 컬럼과 `issue_reason`(이상 사유, 없으면 NULL) 컬럼을 추가한다. 업로드 시점에 아래 규칙으로 자동 판정한다: `fnd_cod`(펀드코드)·`fnd_nm`(펀드명)·`tr_bpr`(거래기준가) 중 하나라도 비어있으면 `issue`("값 없음"), `tr_bpr`이 숫자가 아니거나 0 이하이면 `issue`("거래기준가 값 이상"), 그 외에는 `pending`. `tx_bpr`(과표기준가)·해외비과세과표기준가·Full 거래기준가·소득세법·통화구분 등 나머지 항목은 그대로 저장만 하고 1차 검증 대상에는 포함하지 않는다.
- `price_uploads`에 `status`(`uploaded` | `partially_registered` | `registered`)와 `registered_at` 컬럼을 추가한다.
- 새 페이지 `/price-uploads/[id]`: 해당 업로드의 `price_records`를 표로 보여준다. 기본 표시 컬럼은 일자·펀드명·펀드코드·거래기준가·상태이며, 나머지 항목(운용사코드/운용사명/과표기준가/해외비과세과표기준가/Full 거래기준가/소득세법/통화구분)은 행을 펼치거나 상세보기로 확인할 수 있게 한다. `pending`/`registered` 항목과 `issue` 항목을 구분해서 보여주고, `issue` 항목에는 Badge(red)와 사유를, 정상 항목에는 Badge(green) 또는 등록 여부를 표시한다. 상단에 "정상 N건 / 이상 N건 / 등록완료 N건" 요약을 보여준다.
- 새 API `POST /api/price-uploads/[id]/register`: 해당 업로드의 `pending` 상태 레코드를 모두 `registered`로 바꾸고 `registered_at`을 기록한다. `issue` 레코드는 건드리지 않는다. 처리 후 `price_uploads.status`를 전체가 등록되면 `registered`, 이상 레코드가 남아있으면 `partially_registered`로 갱신한다.
- 등록 버튼은 클릭 시 "N건을 등록합니다" 확인 창을 띄운 뒤 위 API를 호출한다. `pending` 레코드가 0건이면 버튼을 비활성화한다.
- 기준가-파일-업로드 기능에서 같은 날짜 파일을 다시 올려 기존 업로드를 대체할 때, 이미 `registered`된 레코드는 그대로 유지하고 `pending`/`issue` 레코드만 새 파일 내용으로 교체 후 재검증한다. (등록 완료된 값이 재업로드로 인해 사라지지 않도록 한다.)

## Out of Scope

- 이상 항목의 값을 화면에서 직접 수정하는 기능 — 평가사에게 재확인을 요청하고, 정정된 내용이 담긴 파일을 기준가-파일-업로드 기능으로 다시 올리는 방식으로만 처리한다.
- 펀드 평가사에게 자동으로 연락하는 기능 — PRD에서 범위 밖으로 정해짐.
- 이미 등록된 항목을 등록 취소하거나 되돌리는 기능.

## Further Notes

- 이상 판정 기준(값 없음, 기준가 0 이하 또는 숫자 아님)은 1차 기준이다. 운영하면서 "전일 대비 급격한 변동" 같은 추가 기준이 필요해지면 이후에 보완한다.
- 이 화면과 등록 처리 결과는 오늘의-등록-현황, 등록-이력-조회 기능에서 그대로 참조한다.
