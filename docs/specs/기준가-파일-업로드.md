## Problem Statement

업무운영팀 담당자는 매일 아침 펀드 평가사로부터 기준가 txt 파일을 이메일로 받는다. 지금은 이 파일을 열어 내용을 직접 확인해야 하는데, 그 전에 우선 이 파일을 시스템에 편하게 올릴 방법이 없다.

## Solution

담당자가 메일에서 받은 기준가 txt 파일을 화면에서 선택해서 올리면, 시스템이 파일 내용을 구분자로 나눠 읽어서 펀드별 기준가 데이터로 변환해 저장해준다. 이 결과는 바로 다음 화면(기준가-데이터-확인및등록)에서 확인할 수 있는 상태가 된다.

## User Stories

1. As a 업무운영팀 담당자, I want to txt 파일을 화면에서 선택해서 올릴 수 있는 기능, so that 메일에서 받은 파일을 바로 시스템에 넣을 수 있다.
2. As a 업무운영팀 담당자, I want 업로드 버튼을 눌렀을 때 파일이 실제로 처리되고 있다는 표시, so that 처리 중인지 끝난 건지 헷갈리지 않는다.
3. As a 업무운영팀 담당자, I want txt가 아닌 파일을 올리면 바로 알려주는 것, so that 잘못된 파일을 실수로 올렸을 때 바로 알아챌 수 있다.
4. As a 업무운영팀 담당자, I want 업로드한 파일이 구분자 기준으로 잘 나뉘어서 펀드별 줄로 정리되는 것, so that 파일을 직접 열어보지 않아도 내용이 뭔지 알 수 있다.
5. As a 업무운영팀 담당자, I want 파일 형식이 평소와 달라서 제대로 나뉘지 않을 때 오류 메시지로 알려주는 것, so that 잘못된 파일을 그냥 넘기지 않고 바로 알 수 있다.
6. As a 업무운영팀 담당자, I want 업로드가 끝나면 몇 건의 펀드 데이터가 들어왔는지 바로 보여주는 것, so that 파일이 제대로 들어왔는지 한눈에 확인할 수 있다.
7. As a 업무운영팀 담당자, I want 업로드한 파일의 원본 이름과 업로드한 시각이 남는 것, so that 나중에 어떤 파일을 언제 올렸는지 헷갈리지 않는다.
8. As a 업무운영팀 담당자, I want 오늘 이미 파일을 올린 상태에서 다시 올리면 기존 것을 덮어쓸지 물어보는 것, so that 실수로 두 번 올려서 데이터가 중복되지 않는다.
9. As a 업무운영팀 담당자, I want 업로드 후 자동으로 확인 화면으로 넘어가는 것, so that 업로드와 확인 사이에 헤매지 않는다.
10. As a 업무운영팀 담당자, I want 파일 안의 한글(펀드명 등)이 깨지지 않고 제대로 보이는 것, so that 어떤 펀드인지 정확히 알아볼 수 있다.
11. As a 업무운영팀 담당자, I want 업로드한 데이터가 자동으로 오늘 날짜와 연결되는 것, so that 날짜를 따로 입력하지 않아도 된다.

## Implementation Decisions

- 새 테이블 `price_uploads`: 업로드 한 건(=파일 한 개)을 나타낸다. 컬럼: `id`, `upload_date`(업로드된 날짜, YYYY-MM-DD), `original_filename`(원본 파일명), `uploaded_at`(업로드 시각), `status`(`uploaded` — 업로드만 된 상태, 이후 기준가-데이터-확인및등록 기능에서 `registered`로 바뀜).
- 새 테이블 `price_records`: 업로드 한 건에 포함된 펀드별 한 줄을 나타낸다. 파일의 각 줄은 다음 순서로 구성되며, 각각 컬럼으로 저장한다: `price_date`(일자, `'20260914'`처럼 `YYYYMMDD` 형태의 varchar 문자열로 저장하고 대시 등 구분자를 넣지 않는다), `fnd_nm`(펀드명), `fnd_cod`(펀드코드), `mgmt_com_cod`(운용사코드), `mgmt_com_nm`(운용사명), `tr_bpr`(거래기준가), `tx_bpr`(과표기준가), `fr_tax_free_bpr`(해외비과세과표기준가), `full_tr_bpr`(Full 거래기준가), `income_tax_law`(소득세법), `currency_type`(통화구분). 그 외에 `id`, `upload_id`(→ `price_uploads.id`), `raw_line`(원본 줄 텍스트, 문제 생겼을 때 대조용)을 둔다.
- 새 API `POST /api/price-uploads`: `multipart/form-data`로 txt 파일을 받아 서버에서 텍스트로 읽고, 구분자로 각 줄을 위 11개 항목 순서대로 나눠 `price_uploads` 1건과 `price_records` N건을 생성한다. 파일 인코딩은 UTF-8과 EUC-KR(국내 금융권 레거시 파일에서 흔함) 둘 다 시도해서 깨지지 않는 쪽으로 읽는다. 응답으로 업로드 id와 처리된 건수를 돌려준다.
- 구분자는 콤마(,)로 우선 구현하고, 실제 파일에서 다른 문자로 확인되면 맞게 조정한다. 항목 순서(일자/펀드명/펀드코드/운용사코드/운용사명/거래기준가/과표기준가/해외비과세과표기준가/Full 거래기준가/소득세법/통화구분)는 담당자로부터 확인받았다.
- 같은 날짜에 이미 `price_uploads` 레코드가 있는 상태에서 새 파일을 올리면, 기존 업로드(및 그 `price_records`)를 새 업로드로 교체할지 화면에서 확인받는다. 확인하면 기존 레코드를 지우고 새로 만든다.
- 새 페이지 `/price-uploads`: 파일 선택 input과 업로드 버튼, 업로드 진행 상태 표시, 업로드 완료 후 처리 건수 요약을 보여준다. 업로드가 끝나면 기준가-데이터-확인및등록 화면으로 이동한다.
- `app/layout.tsx`의 nav에 이 페이지로 가는 링크를 추가한다.

## Out of Scope

- 메일함에서 파일을 자동으로 가져오는 것 — PRD에서 범위 밖으로 정해짐. 담당자가 직접 파일을 선택해서 올리는 방식만 다룬다.
- 업로드된 데이터에 이상한 값이 있는지 확인하고 등록하는 것 — 기준가-데이터-확인및등록 기능에서 다룬다.
- 펀드 운용시스템에 값을 넣는 것 자체 — 기준가-데이터-확인및등록 기능에서 다룬다.

## Further Notes

- 구분자 문자(콤마로 가정)와 인코딩(UTF-8/EUC-KR)은 실제 파일 샘플로 최종 확인이 필요하다. 항목 순서와 구성은 담당자로부터 확인받아 확정했다.
- "덮어쓰기 확인"은 같은 날짜 기준이며, 등록(`registered`)까지 끝난 업로드를 덮어쓰는 경우의 처리는 기준가-데이터-확인및등록 스펙에서 함께 다룬다.
